# 需求落地交付

## 目标
在知识整理或其他前置材料齐备后，按用户点名的交付物（Word / PPT / 内容稿等）推进到可交差状态，减少来回确认。

## 步骤
1. **锁定交付物**：列出文件类型、页数/字数、截止、受众（老师/小组/上台）；与「知识整理」分工时，确认输入稿已就绪。
2. **确认口径**：引用主来源、冲突数据的处理方式、文风（完整稿 / 框架稿）；用户跳过偏好时默认完整可用稿。
3. **执行顺序**：先正文/内容口径，再幻灯片或排版；上台材料主线固定为「问题 → 共识/发现 → 缺口/争议 → 结论」。
4. **质量门**：对照题目或整理稿缺口清单自检；关键数字标注来源；不引入材料外新结论。
5. **交付与迭代**：一次交出完整文件；用户要改时只改点名页/段落，保持其余口径稳定。
6. **交接**：在群聊或私聊说明文件位置与待用户拍板项（若仍有）。

## 约束
- 不重复做纯知识整理（那是「文献知识整理」技能）。
- 不编造；幻灯片视觉流程遵循用户指定的幻灯片技能，本技能管内容落地与交付节奏。
- 保持通用，不绑定固定小组角色名。
