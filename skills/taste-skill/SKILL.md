# Taste Skill 设计审查（设计总监）

本地完整安装路径：`/home/box/agent-data/taste-skill`
默认技能目录：`/home/box/agent-data/taste-skill/skills/taste-skill`
上游：https://github.com/Leonxlnx/taste-skill（install name: `design-taste-frontend`）

本技能用于**审查与把关**，不是默认代做整站。先出诊断与改稿清单；只有用户明确要求改实现时再动手。

## 审查流程（按顺序）

### 1. 弄清审查对象
- 拿到 URL、截图、HTML/前端源码，或设计稿。
- 记下主体、受众、主转化动作、是否已有品牌色/字体、现有图片是否真实可用。
- 请求含糊时先写一句自己的理解再审，缺关键事实才追问。

### 2. 能跑脚本就跑门禁
在项目根目录执行（`<skill>` = 上面的默认技能目录）：

```bash
node <skill>/scripts/lint.mjs <源码或目录>
node <skill>/scripts/inspect.mjs <url 或 path/to/index.html>
```

- 所有 `FAIL` 必须修；`WARN` 默认当问题，除非能用一句话向设计师辩护。
- 无 Node 22 / Chrome 时：用现有截图工具取 1440 / 768 / 390，并在报告里写明 inspector 未跑。
- 细项读取：`references/tells.md`、`references/critique.md`、`references/type.md`、`references/colour.md`、`references/layout.md`、`references/imagery.md`、`references/motion.md`。

### 3. 只看图做评审（十四遍）
打开截图（不要对着代码脑补意图），按 `references/critique.md` 做十四遍：一秒焦点、眯眼质量块、盖住 logo 的竞品测试、左缘对齐数、间距、字号跳跃、配色比例、真实图片数量、区块同质化、手机是否独立构图、信息密度、内容是否完整、碰撞/溢出、竞品替换 + 一个可互动的 live thing。

### 4. 打分
Awwwards 权重：设计 40% · 可用性 30% · 创意 20% · 内容 10%。写清四项分与总分。

硬上限（覆盖算术）：
- 仍有 inspect `FAIL` → 总分 ≤ 6.0
- 截图里可见：三行以上标题、eyebrow、等宽标签、01/02/03、装饰渐变、静止元素投影、装饰细线 → 总分 ≤ 6.5
- 盖住 logo 后仍像通用站 → 创意 ≤ 6
- 真实图片不足 4 张（绘图不算）→ 设计 ≤ 6.5
- 几乎无动效或全站同一淡入 → 设计 ≤ 7
- 无 live thing → 创意 ≤ 7.5
- 仍有占位灰块 / lorem → 内容 ≤ 5

### 5. 交付审查报告（简体中文）
结构固定：
1. **总评一句**（能不能过、像不像 AI 模板）
2. **四项分 + 总分**（写明是否触发硬上限）
3. **硬伤清单**（对照下方 House rules，按严重度排序）
4. **改稿优先级**（最多 3–5 条，写清「改什么 / 为什么 / 建议成什么样」）
5. **可保留的优点**（避免只挑刺）
6. **未跑的检查**（如实写）

最多三轮「改→再看截图→再打分」。不要声称没跑过的检查。

## House rules（审查红线）

| 违规 | 应改成 |
| --- | --- |
| 标题任意宽度超过两行 | 砍字 → 再加宽字距 → 最后才缩字号 |
| Eyebrow / 药丸角标 / New·芯片 | 信息进标题或首句，否则删 |
| 等宽字体用于装饰标签 | 正文族；对齐数字用 tabular figures |
| 01/02/03 步骤编号 | 用位置、尺度或文字表达顺序 |
| 细分割线、1px 描边框、网格线 | 留白、底色台阶、尺度对比、色块 |
| 渐变背景/按钮/字 | 纯色或真照片；照片上中性遮罩是唯一例外 |
| 静止元素投影/光晕 | 表面用色阶；只有真正浮层（菜单、对话框）可投影 |
| 助手调色板（米黄+陶土、紫/靛） | 项目方向盘指定的色板 |
| 极小大写字距标签 | 句首大写、可读字号 |
| 图标顶栏三卡片、相同卡片横排 | 按方向盘区块蓝图 |
| 毛玻璃、浮动药丸导航 | 普通顶栏：字标 + 少量链接 + 一个主操作 |
| Emoji、装饰 blob、假仪表盘灰条 | 真图、真界面片段，或什么都不要 |
| 标题里单独强调一词（斜体/衬线/彩色） | 同一字族、同一颜色 |
| 超过两种字族 | 通常一种，最多两种 |

## 设计总监立场
- 默认产出是**审查意见**，不是重做整站。
- 改稿意见要可执行：点名区块、具体手法，禁止空话（「更高级」「更有质感」）。
- 去掉装饰却不补实质（更大字、满内容、真图、色场）会更薄——盲测里「干净但空」会输给「花但满」。审查时同时抓模板味与空壳感。
- 已有品牌时：保留品牌色/字，只审构图与 house rules；品牌本身要求违规装置时，注明例外并只放行该项。
- 仪表盘/应用内屏：本技能不适用；改用产品 UI 审查逻辑，勿硬套落地页规则。
